## 원인 대조

1. **분류 누락: 확인.** 실제 새 글은 들어왔지만 모두 분류가 비어 있었다.
   [DevDay 답글](https://x.com/thsottiaux/status/2104462713296683467)은
   9월 28일 15:46:24 KST 게시 시각 근거에 대해 15:48:17에 관측됐다.
   `DevDay`가 제품 문맥 목록에 없어 이 단계에서 제외됐다. 전체 11개가 중요 공지라는 뜻은
   아니다. 사진 소개, 인사, 짧은 답글도 포함돼 있다.
2. **상류 수집 중단: 전체 기간의 원인으로 볼 근거 없음.** 새 ID 11개가 관측됐다.
   `/tibo`만 9월 27일 23:39~23:50 KST에 503을 7회 반환했고 다른 endpoint는 정상 응답했다.
   TwiScan의 최신 ID는 계속 9월 26일 글이었고 확정 리셋 API의 기록은 55개로 유지됐다.
   새 글이 없다는 사실만으로 이 두 소스의 장애를 확정하지 않는다.
3. **실행 공백: 이번 측정 구간에서 기각.** 2분 수집이 계속됐다.
4. **중복 처리·Discord 실패: 이번 새 글 무알림을 설명하는 추가 원인으로 확인되지 않음.**
   새 글은 분류 단계부터 대상이 아니며, 전송 시도 자체가 없다. 운영 상태 전체를 읽어
   검증한 것은 아니고 현재 Discord 토큰·권한의 유효성도 발송 테스트로 확인하지 않았다.

X 직접 조회는 403으로 실패했다. 내용과 원문 링크는 실제 수집한 공개 피드 및
[Tibo 타임라인](https://codex-reset.com/tibo)에서 대조했다. X의 전체 글을 빠짐없이
수집했다고 주장할 수는 없다. 원문 시각은 피드 필드 또는 X ID 변환 근거다.

## 추가로 재현한 리셋 분류 결함

피드의 `signal` 글인 [다음 주 리셋 예고](https://x.com/thsottiaux/status/2103963215885701493)는
복수형 `resets`를 쓴다. 분류기는 구조화된 리셋 태그가 있어도 단수형 단어 `reset`만
인정해 이 글을 제외했다. `candidate`의
[리셋 전파 완료 글](https://x.com/thsottiaux/status/2103911959544610829)도 같은 문제가 있다.
후자는 확정 리셋 API에서 별도 분류되므로 이 결함만으로 최종 전송 누락을 단정하지 않는다.
두 글은 41시간 측정 시작 이전 글이므로 새 글 11개에 포함되지 않는다.

## 최소 수정과 검증

- 기존 구조화된 리셋 태그 조건 안에서만 `resets`를 `reset`과 함께 인정한다.
  일반 대화의 복수형을 무조건 리셋으로 처리하지 않는다.
- `DevDay`를 OpenAI 문맥으로 인정한다. 행사명만 있는 답글은 `OpenAI 소식`으로
  분류하며 확정 출시라고 부풀리지 않는다. 이는 기존 누락 방지 우선 정책의 좁은 보정이다.
- 분류 단위 테스트와 실제 파서 → watcher → 발송 콜백 회귀 테스트를 추가했다.
  같은 snapshot을 다시 처리해도 한 번만 알린다.

수정 전 `python -m pytest -q tests/test_classifier.py tests/test_notification_regressions.py`:
**5 failed, 38 passed**. 수정 후 전체 Python **277 passed**, Actions 연결 Node 검사 **13 passed**.
실제 최신 타임라인 10개를 별도 초기 상태에 재생하면 수정 전 **알림 0건**, 수정 후
**DevDay 알림 1건**이다. 이는 로컬 콜백 검증이며 Discord 실발송 성공을 뜻하지 않는다.

운영 상태나 중복 방지 기록은 수정하지 않았다. 이미 처리한 글은 규칙을 수정해도
자동으로 소급 발송되지 않는다. 별도 재처리 기능이나 과거 알림 일괄 발송은 이번 수정에
포함하지 않는다. 브랜치 수정은 운영 기본 브랜치에 반영되기 전까지 실제 감시에 적용되지 않는다.
